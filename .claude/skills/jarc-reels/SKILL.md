# 자르크 릴스 만들기

사용자는 개발자가 아니다. 진행 상황은 "2/6 원본 정리 끝"처럼 한 줄로, 결과는 쉬운 말로 알린다.

## 1. 날짜와 폴더
- 날짜를 `YYMMDD`로 정한다. "오늘"이면 오늘 날짜. 이것이 `<id>`다
- `ls "$HOME/Library/Mobile Documents/com~apple~CloudDocs/JARC릴스/<id>"`로 영상이 있는지 본다
- 폴더가 없거나 비어 있으면 사용자에게 아이폰 파일 앱으로 올려 달라고 하고 멈춘다 (SETUP.md 4번 안내문)

## 2. 원본 정리
```bash
zsh scripts/prepare.sh <id>
```
- 영상을 촬영 순서대로 `public/sessions/<id>/c01.mp4…`로 바꾼다 (세로 1080×1920, HDR은 색 보정, 소리 없음)
- `work/<id>/cNN_sheet.jpg`: 0.5초 간격 장면 시트. 왼쪽 위부터 한 줄에 8칸. k번째 칸(0부터) = k×0.5초
- `work/<id>/clips.tsv`: 길이, `best_start`(움직임이 가장 큰 1.5초의 시작). **참고만 한다.** 사람이 카메라 앞을 지나가는 구간도 움직임이 크게 나온다
- 사진은 `work/<id>/photos/`에 jpg로 있다 (와드 화면·화이트보드 사진일 수 있음)

## 3. 와드 확인
순서대로 시도한다.
1. Notion: `notes/notion.md`에 적힌 방법으로 그날 운동기록을 찾는다
2. 사진: `work/<id>/photos/`에서 와드가 찍힌 사진을 읽는다
3. 둘 다 없으면 사용자에게 묻는다: "오늘 와드 제목이랑 종목 순서 알려 주세요"

정리할 값: `title`(예: Run & Station Interval), `summary`(예: 3분 RUN + 2분 STATION × 6 SETS), `sets`(종목 순서, 화면에 1부터 번호가 붙음). 원문 표기를 그대로 쓴다.

## 4. 컷 고르기
모든 `cNN_sheet.jpg`를 Read로 본다. 고르는 기준:
- 컷 **12~18개**, 합계 **20~28초**. 컷 하나는 **1.0~1.5초**
- 첫 2~3컷은 와드가 떠 있는 동안이다 (`wodCuts`). 이 컷들은 2~2.5초씩, 합계 **4.5초 이상**이 되게. 러닝처럼 여러 명이 보이는 장면이 좋다
- **수업 순서대로** 놓는다. 같은 장면이 연달아 나오지 않게 섞는다
- 뺄 것: 사람이 카메라를 가리는 구간, 크게 흔들리는 구간, 기구 세팅·쉬는 장면, 화면이 너무 어두운 장면(써야 하면 `brightness: 1.2~1.4`)
- 동작의 힘이 들어가는 순간(당기기, 밀기, 던지기)이 컷 안에 들어오게 `start`를 잡는다
- 사람이 화면 가장자리에 잘리면 `centerX`(0~1, 사람이 있는 쪽)와 `zoom`(1.1~1.3)으로 맞춘다
- 마지막 컷은 여럿이 같이 나오는 장면을 추천한다 (화려한 버전에서 네모 창으로 열림)

## 5. 세션 파일 쓰기
`sessions/<id>.json`을 `sessions/sample.json`과 같은 형식으로 쓴다.
```json
{ "session": {
  "id": "<id>", "date": "11.23",
  "wod": { "title": "...", "summary": "...", "sets": ["..."] },
  "wodCuts": 3,
  "cuts": [ { "src": "c01.mp4", "start": 0.5, "seconds": 2.2 }, ... ]
} }
```
- 컷 옵션: `zoom`, `centerX`, `centerY`, `brightness`, `enter`(화려한 버전 전환: none·black·glow·punch·slash·box, 비우면 자동)
- 화려한 버전은 컷을 1.2초(마지막 1.5초)까지만 쓴다. 담백 버전은 적은 길이 그대로

## 6. 정지 화면으로 확인
```bash
npx remotion still plain work/<id>/check_<frame>.jpg --props=sessions/<id>.json --frame=<frame> --scale=0.3
```
- 담백: 와드 화면(30프레임)과 컷 3~4곳. 화려: 인트로(60), 컷 몇 곳, 마지막 네모 창
- 볼 것: 와드 글씨가 사람 얼굴을 가리는지, 사람이 잘렸는지, 빈 화면·가림이 섞였는지
- 문제가 있으면 세션 파일을 고치고 다시 본다

## 7. 샘플 렌더
```bash
zsh scripts/render.sh <id> sample
```
- 결과: `out/<id>-plain_sample.mp4`, `out/<id>-flashy_sample.mp4`, iCloud `JARC릴스/<id>/output/`
- `open`으로 열어 주고, 짧게 알린다: 길이, 컷 수, 와드 내용, 확인이 필요한 점(예: 와드를 사진에서 읽음)
- 묻는다: "고칠 곳이 있으면 몇 초쯤인지 알려 주세요. 괜찮으면 '최종'이라고 해 주세요"

## 8. 수정 요청
- 사용자가 말하는 시간은 **완성 영상 기준**이다
  - 담백: 컷 `seconds`를 앞에서부터 더해 몇 번째 컷인지 찾는다
  - 화려: 인트로 3.2초 + 컷마다 min(seconds, 1.2) (마지막은 1.5)
- 고친 뒤 6번(정지 화면) → 7번(샘플)을 다시 한다

## 9. 최종
사용자가 "최종", "좋아", "올릴게"라고 하면:
```bash
zsh scripts/render.sh <id> final
```
- 결과: `out/<id>-plain.mp4`, `out/<id>-flashy.mp4`, 커버 이미지 `_cover.jpg`, iCloud `JARC릴스/<id>/output/`
- 알린다: "아이폰 파일 앱 → JARC릴스 → <id> → output에 있어요. 음악은 인스타에서 붙여 주세요"
- 원하면 업로드 문구 두 가지를 짧게 제안한다 (와드 요약 + 해시태그 #하이록스 #hyrox #자르크). 영상에 없는 내용은 쓰지 않는다

## 막혔을 때
| 증상 | 할 일 |
|---|---|
| "iCloud에서 원본 내려받는 중"이 오래 걸림 | 아이폰·맥이 인터넷에 연결돼 있는지 확인 후 다시 실행 |
| 렌더 실패 | `work/render-<plain|flashy>.log`를 읽고 고친다. 세션 파일 형식 오류면 메시지에 틀린 칸이 나온다 |
| 원본이 1~2개뿐 | 한 영상에서 여러 구간을 잘라 쓴다 (같은 `src`, 다른 `start`) |
| Notion 도구가 없음 | SETUP.md 3번으로 연결을 안내하고, 이번엔 사진이나 사용자 답으로 진행 |
